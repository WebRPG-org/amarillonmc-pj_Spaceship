## 物资、敌人和禁区

30 个箱子使用现有本局共享容器事务。分为医药、合成材料、弹药和投刃／火枪／法杖／棒槌武器箱，同一局只能由一人领取一次，不同局独立；不写入局外永久背包。拾荒者 HP 110、攻击 20；巡查员 HP 180、攻击 28。总共 28 名敌人，掉落恢复物品，死亡后本局不重生。数值是初始可玩配置，尚未经过多人平衡试玩。

现代区关闭时间相对开局计时，各提前 30 秒预警：

- 6:00：电玩城、夜店、酒店。
- 8:30：学生宿舍、健身房、游泳馆。
- 11:00：影院、地下维护、地铁站厅。

村屋封锁控制台同时解除以上普通禁区；矿道持续禁区和原结局不变。离线搜箱及禁区撤离走相同的静态传送口。

## 图块、通行与编辑

从 `D:\Resources\RM_Resources\RMTiles` 选择 8 个素材包，共导入 30 张 PNG，统一前缀 `BR_`，新增 Tileset 031–038；健身房和泳池共用 Pool 图块集。资源包、Sample Tilesets.json 路径、Sample 图块集 ID、目标文件名及例外记录在 `data/modern-map-sources.json`。素材仍受各自原授权约束。

直接复制各自 Sample 的完整 flags，保留四方向通行、星标、梯子及其他标志。仅针对本次场景做两项显式调整：

- 所有新图块集的 A4 黑色剖面屋顶 `5888–5935` 设为四向阻挡，作为室内地图边界。
- Pool 的蓝色池底 `2960–3007` 设为四向阻挡，表示深池；当前没有游泳机制。

A2/A4 根据相邻格计算自动图块形状。B 图块按 RPG Maker 的左右两个 8 列区域编码，完整保留多格物件的上层遮挡和下部碰撞。夜店采用 Sample 已配置的第一列霓虹墙，避免使用超出 flags 长度的第五列墙。

地图文件是标准六层 RPG Maker JSON，可以在原工程直接编辑。地图 note 保留 `<modernRound>`；箱子第一页注释为 `engine_container : medical` 等类型，敌人第一页同时包含 `enemy_id : 4` 与 `engine_enemy : scavenger`，或 `enemy_id : 9` 与 `engine_enemy : guard`。本局共享奖励与敌人数值由 `engine/server/modern-district.mjs` 应用；旧 MV 插件客户端不实现这些共享箱子规则，实际游戏请使用新引擎。

`engine/tools/build-modern-maps.mjs` 保存本轮手工布局蓝图、资源导入和自动图块算法。若需从本轮蓝图重建，在仓库根运行：

```powershell
node engine/tools/build-modern-maps.mjs 'D:\Resources\RM_Resources\RMTiles'
```

此命令会覆盖 Map031–039、对应 Tileset 与 MapInfos 条目，并更新道路中具名的接驳事件；手工编辑地图后不要重新运行，除非希望恢复蓝图版本。日常编辑后重启引擎并刷新客户端即可。

## 验证

- 自动测试覆盖全部地图六层结构、资源存在、实体通行、每个实际入口到箱子／敌人／出口的可达性、跨图连通和全部新传送事件实际执行。
- 使用实际 Round 和 World 验证每个新箱子的同局唯一领取、跨局独立，敌人死亡掉落和不重生，以及全部新区的禁区启用和控制台解除。
- 实际客户端 Renderer 在无头 Edge 中逐张渲染九张地图，所有图块与事件图片加载成功，无页面 JavaScript 错误。逐图截图和总览位于 `engine/.artifacts/modern-maps/`；这些是本地验收产物，不提交到仓库。
- 原副本的普通撤离、完整 Boss 路线、鼠标移动、武器消耗和事件测试继续运行；实际 MySQL／HTTP／双 WebSocket 测试单独执行。

最终检查结果：`npm --prefix engine test` 为 105 项通过、4 个数据库组按默认配置跳过；单独运行 `npm --prefix engine run test:integration` 为 23 项通过，无跳过或失败。HTTP 遍历覆盖全部 39 张地图，36 张有可用出生点。新增现代区测试共 9 项，其中实际离线探物从原始副本出生点搜刮村口及道路箱后自行走入新区，现代禁区预警中的离线躲避能够出图且保持满血。`content:check` 中新地图没有不支持命令或运行诊断。
