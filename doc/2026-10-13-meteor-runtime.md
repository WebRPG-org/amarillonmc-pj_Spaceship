# 陨石、实时 NPC 与商店运行规则

本轮运行模块：`engine/server/hazards.mjs`、`npcs.mjs`、`shops.mjs`；规则源为 `engine/content/gameplay.json`。这些规则由服务端执行，客户端只显示预警、动画和交易界面。

## 两种陨石

| 规则 | 废城环境陨石 | 武器「飞火流星」 |
| --- | --- | --- |
| 启用 | `scenario.type === "adventure"` 且配置 `meteor` | 副本 `allowedTitles` 包含 `meteor`，并实际装备武器 65 |
| 室外判断 | 当前地图 ID 属于 `outdoorMapIds` | 同左 |
| 落点 | 每 5 秒记录玩家当时的地图、格子；固定预警 1 秒后落下 | 发动消耗当前全部 MP，10 秒后读取施放者届时的地图和格子 |
| 范围 | 中心及周围八格，精确 3×3 | 同左，包括自身、友方；无视普通 PvE 玩家互伤限制 |
| 伤害 | 默认 400；配置 `meteor.damage` | 默认消耗 MP × 8；配置 `meteorWeapon.mpMultiplier` |
| 可受伤对象 | 玩家、战斗 NPC、带结构标记的事件 | 玩家、战斗 NPC |
| 中断 | 预警已生成后，即使原地图无人仍会结算 | 死亡、进入室内或真正离开实例立即取消，MP 不返还 |

武器的一次引导结束后，可以补 MP 再发动；同一角色已有引导时不允许叠加。MP 支付经过当前世界库存事务，支付失败不产生引导。死亡或离开即使发生在支付事务返回之前，也不能晚到地创建引导。留场断线角色仍存在于实例，其已支付的引导继续；离开世界并移除角色则取消。

普通攻击键可使用武器 65，技能 305 的直接请求也会校验实际装备。鼠标点选敌人时，流星武器直接在自身开始引导，不会先自动走到近战距离。

快照 `hazards` 提供服务端开始/落地时刻、格子和种类。客户端用红色九格显示固定环境落点，用黄色九格与倒计时显示随本人移动的引导；落地复用动画 123，并叠加冲击环和碎片。

## 实时 NPC、结构与掉落

事件 Note 或注释写 `engine_npc:scavenger`，即可绑定 `gameplay.npcs.scavenger`。模板保存名称、HP/MP、属性、金币、经验和带概率的掉落表。现代地区原有 `engine_enemy` 标记也直接绑定这套模板；旧 `enemy_id` 注释仍保留，但这些 NPC 不读取 RM 敌人数据库。运行实体使用 `npcKey` 保存模板身份，`enemyId: -1` 仅供现有导航与界面的敌人识别兼容。

玩家击杀继续使用金币/经验与物品掉落的同一事务。没有玩家归属的环境击杀使用 `createWorldDrops` 原子生成掉落；金币成为可拾取的钱堆，不会授予旁观玩家经验或金币。失败提交使用同一请求身份重试。拾取钱堆与增加钱包金额仍在同一事务完成。

`engine_structure:barricade` 绑定结构耐久，默认 300。环境陨石可击破它；击破后事件消失并解除事件碰撞，不修改原始地图文件或其他实例。完整结构不显示重复悬浮名字，受损时显示耐久条。

## 商店

商店配置包括 `name`、`scope`、`mapId`、`eventId`、`goods:[{kind,itemId,price}]`、`buyOnly` 和 `sellRate`。事件 Note 或注释的 `engine_shop:key` 优先绑定；没有显式标签时才按定义的地图/事件 ID 绑定，现有 DTS 补给商人也可由副本入口布置。`scope:world` 只用于主世界，`scope:dts` 只用于 DTS，省略 scope 可以用于单人冒险等任意世界。商店事件服务为 `{kind:"shop",shopId}`，交易时再次检查作用域。

交互发送 `type:"shop"` 展示消息；买卖命令同样为 `type:"shop"`，包含 `action`、`shopId`、`eventId`、物品类型/ID、数量和唯一请求 ID。出售武器还必须指定其 `instanceId`，一次出售一件。服务端每次交易都重新检查当前地图、事件有效页和一格交互距离，忽略客户端价格。当前世界的钱包、物品栏和武器身份在同一事务内更新，重复请求不会再次付款或回滚到旧余额；COMMIT 响应丢失时由经济状态恢复流程重读库存。

## 验证与地图修正

`engine/test/hazards-shops.test.mjs` 覆盖精确九格、固定与延迟落点、友伤/自伤、室内禁止/中断、死亡/离开/断线竞态、环境无归属掉落与重试、交易范围/伪造价格/重复请求及丢失 COMMIT 响应。既有武器、导航、现代区与 3D 渲染测试同时验证兼容性。

主城额外修正：Map040 的三处门牌交互移到门前人行道；Map044 的四格导览牌保留完整外观，由可接近的下排两格承担相同对话，上排作为牌面。23 项主城可达性/往返测试通过。实际客户端 Renderer 的前后全图与视口位于 `engine/.artifacts/public-city-access-before` 和 `public-city-access-after`，无缺图或渲染异常。该渲染检查不代替连接真实服务的多人试玩。

## 集成复核与修复

复核了 `instances.mjs`、`rounds.mjs`、`persistence.mjs` 和 `round-store.mjs` 的当前调用链，发现并修正：

- 副本定义使用普通对象索引时，`__proto__` 等非自身属性可能通过存在性检查，并在创建数据库记录之后才构造失败。入口现检查字符串类型和自身属性，构造异常也会关闭创建失败的局。
- 只检查内存中已完成创建的副本数量不能限制并发创建。现以 `pendingCreations` 在数据库等待前预留容量，完成或失败均释放预留。
- 冒险地图的应急箱原先只有 `engine_container` 标记。现绑定场景的 `containerLoot` 与已有共享容器事务，首次交互直接给予局内补给，重复交互不重复发放；不要求支付主世界金钱。
- 工作台保存的 `engine_shop` 标签现已接入运行时，并覆盖主世界、DTS 与无 scope 的冒险商店绑定测试。

数据隔离检查中，玩家命令会重新选择当前世界实体并校验 `contextInstanceId`；局内库存、金币、地面物品与请求记录使用 RoundStore 的局号作用域。返回主世界重新加载外部存档，永久奖励仅取服务端副本配置，并与成功结算写入同一事务。外观/离线策略使用资料补丁更新，不允许客户端提交头衔获得列表或自定义奖励。未发现客户端命令直接将局内钱包/物品覆盖主世界状态的路径。
