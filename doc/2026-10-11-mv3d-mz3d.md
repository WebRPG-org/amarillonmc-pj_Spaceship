# MV3D / MZ3D 0.9.2.8 显示接入

新浏览器引擎现在读取 MV/MZ 编辑器中的地图备注、图块集备注、事件备注及当前事件页注释，用用户提供的 **0.9.2.8 原版渲染器**生成 3D。地图、灯光、阴影、坡面、自动图块、材质、模型、天空和后处理使用原配置解析器与 Babylon 渲染实现。没有把图块重新解释为简化方块。

全局仍是 **2D**，只有地图明确写 `enable()` / `enable(true)` 才创建 3D 运行时。既有 Map006 保留；Map040 等公共城市和默认出生配置不变。即使插件参数中的 mapDefaults 写 enable(true)，新引擎也要求地图单独启用，满足本工程的默认 2D 约定。

## 编辑器配置

在地图备注中写：

```text
<mv3d>
enable(true)
camera(0,60,dist:9,height:0.75)
ambient(#c3d2dc)
fog(#c6f0f2|20,45)
sun(white|45,45)
</mv3d>
```

`<mz3d>` 是同义标签；标签本身不决定选用哪套引擎核心。图块集 `<mv3d>` / `<mz3d>`、地图局部 `<mv3d-regions>` / `<mv3d-tiles>`、事件备注和注释的完整原版配置都直接交给新版解析器。不要将 `<mv3d-regions>` 中的区域 ID 当作本工程副本禁区规则。

插件参数继续读取根目录 `js/plugins.js` 中的 mv3d/mz3d 条目，包括旧条目 status:false 时保留的设置；缺少的新参数使用对应 0.9.2.8 插件头的默认值。启用的条目优先。编辑后重启服务并刷新浏览器。旧客户端的 `js/plugins/mv3d.js` 0.6.6 和关闭状态保留，新引擎实际加载 `engine/client/vendor/3d/` 的新版。若在旧 MV 编辑器里需要新版插件管理器的参数面板，需在该旧客户端安装用户提供的新版插件；新引擎不依赖旧插件文件。

## 输入和联网状态

3D 地图右上角提供相机旋转、俯仰按钮，右下角缩放继续可用。单击以 Babylon 射线拾取地形或角色，发送原有服务端寻路意图；角色名称、血条、对话定位和聊天气泡按角色实际 3D 高度投影定位。

每张 3D 地图使用独立 iframe 保存 RPG Maker / 插件全局对象，仅运行展示更新。服务端快照决定角色位置、朝向和有效事件页；缺席或无有效页的事件不显示、不保留灯光。自定义角色外观由现有外观组合器生成后交给原 3D 角色材质。地图切换和同地图 ID 的副本切换都会释放旧场景；返回 2D 不保留其相机或灯光。

宿主不启动 RPG Maker 的 SceneManager 主循环，不运行事件解释器、自动移动路线、旧网络插件、存档或音频。服务端仍负责事件、碰撞、移动、战斗与存档。

## 视觉命令

MV 的插件命令 356 和 MZ 的结构化插件命令 357 经过明确的服务端适配，再交给原版视觉命令函数。包括 camera（含 2D / perspective / orthographic 模式）、pan、fog、ambient/light、sun、lamp、flashlight、skybox/skyball、elevation、enable/disable、resolution 和限定的 set/configure。天空文件使用本地文件名或子路径。未知命令进入兼容报告，不执行任意 JavaScript。

例如：

```text
mv3d camera yaw +90 1
mv3d camera yaw +-90 1
mv3d fog #c6f0f2 20 45 0
mv3d @player flashlight white 1.5 6 60 0
mv3d @player flashlight black 0 6 60 0
```

`+-90` 是原版的相对减少写法，`-90` 是绝对角度。地图 / 图块集 / 事件配置引用的 `var(n)` 从服务端的个人变量同步；原版会动态计算的表达式继续动态计算，原版只在读取时计算的字段保持该语义。视觉命令带地图与副本上下文，在异步载图期间排队。命令属于当前个人演出，不持久重放相对相机和灯光变化；固定入图效果应写地图或事件配置，或由服务端入图事件重新设定。

## 验证及范围

真实浏览器 WebGL 验证工具：

```powershell
node engine/tools/verify-3d.mjs
$env:PLUGIN_3D='mz3d'
node engine/tools/verify-3d.mjs
```

可通过 `MAPS_3D` 指定地图，`SAMPLE_3D` 指向只读 Sample 目录；`PLAYWRIGHT_MODULE` 和 `BROWSER_EXECUTABLE` 可覆盖浏览器路径。输出在 `engine/.artifacts/3d/`，MZ 在其 `mz3d/` 子目录。可选纹理配置和法线等文件的 HEAD 404 是原插件存在性探测，与必需素材的 GET 失败分开记录。

本次已验证两版渲染器加载 Map006/049/050/051、真实几何和灯光、切回 2D、角色视口、相机命令、手电筒；额外使用 Resources Sample 验证 OBJ、GLB、自定义 mesh 和天空背景。坡道用原版 getWalkHeight 连续采样，三图全部交互点用服务端实际碰撞检查。

最终检查记录（2026-10-11）：

- `npm --prefix engine run test:3d`：MV、MZ 各 4 张地图通过，包含动态开关 3D、开启前的相机设置、异步灯光命令顺序和回收场景。
- `node engine/tools/verify-3d-entities.mjs`：两版均通过克隆事件独立配置、精准灯光命令、切页与隐藏恢复、首次角色高度与瞬移高度检查。
- `node engine/tools/verify-3d-ui.mjs`：实际应用预览三图、相机按钮、缩放和返回 2D 通过。
- `npm --prefix engine run test:integration`：23/23，通过真实 MySQL、HTTP 和 WebSocket；51 张地图可加载，48 张可传送，3 张原空地图正确报告无出生点。
- `npm --prefix engine test`：203 项中 196 通过、4 跳过、3 失败。失败为既有 Map040 / Map044 的 NPC 接近路径问题及其父测试；本次未改动这两张地图及它们使用的图块集。

这次接入的目标是地图与角色 **3D 显示配置**。原插件的立体物理、桥上桥下同时通行、载具 / 飞行、任意 JS 插件脚本和完整事件模型动画逻辑没有替换服务端现有规则。战斗动画继续使用本引擎已有的 MV 动画 / MZ Effekseer 显示层，尚未迁移原插件的 animationDepth 立体动画。这些不能据“地图已显示”宣称完整等价。也未对全部参数组合做逐像素 / 逐帧对照。

运行库原文件及 SHA256 来源见 [SOURCE.json](../engine/client/vendor/3d/SOURCE.json)，导入脚本为 `engine/tools/import-3d-runtime.mjs`。商业插件与 RPG Maker 核心保留原版权说明，不被本适配重新授权。
