# Spaceship 新引擎开发原型

这是第二阶段的可运行原型：使用独立浏览器客户端、服务端世界模拟和 MySQL，读取现有 RPG Maker 地图、数据库与素材。现在可以从外部世界 NPC 进入独立 PvE / PvPvE 副本，走通普通撤离或 Boss 终局，并保存自定义角色外观。支持鼠标寻路与互动、四种离线策略、按武器消耗耐久／弹药／MP，以及真实 MZ Effekseer 粒子。当前仍不适合直接部署为公开运营 MMORPG。

旧客户端、插件和 `server/` 保留。新引擎从仓库根目录直接读取 `data/`、`img/`、`audio/`、`effects/`，无需复制或转换整批素材，也不要求放弃此前积累的 RPG Maker 素材库。原 RethinkDB 账号和存档**不会自动迁移**；新引擎使用自己的账号与数据库。

## 在 Windows 本机启动

需要 Node.js **22 或更新版本**、npm、PowerShell；首次安装需要联网下载依赖及官方 MySQL 压缩包。在仓库根目录的终端执行：

```powershell
cd engine
npm install --cache .local/npm-cache
npm run mysql:start
npm run dev
```

打开 [http://127.0.0.1:8098](http://127.0.0.1:8098)。创建账号后即可进入在线世界；也可以点击“先浏览现有地图”，在不登录、不运行战斗的情况下检查地图与素材。

**首次使用独立 MySQL 脚本时，不要先将 `.env.example` 复制为 `.env`。** `mysql:start` 会自动创建随机凭据、应用账号和 `engine/.env`。若数据库尚未初始化而 `.env` 已存在，脚本会保留文件并停止，以免覆盖已有连接配置。`.env.example` 供手动连接自己管理的 MySQL 时参考，其中的示例密码不能直接用于自动创建的实例。

本项目的数据库实例为 **MySQL 8.4.11**，绑定 `127.0.0.1:3317`。程序、日志、凭据和数据库文件均位于 `engine/.local/`，数据目录为 `engine/.local/mysql-data/`。它不安装 Windows 服务，也不修改已有的 **MySQL57** 服务或其数据；若指定端口被其他实例占用，脚本会停止。`engine/.local/`、`.env` 和生成的 `.artifacts/` 已列入 Git 忽略。

`mysql:start` 生成的 `.env` 默认包含：

```dotenv
HOST=127.0.0.1
PORT=8098
DEV_TOOLS=1
```

已有 `.env` 不会被自动改写；需要开发测试入口时自行加入 `DEV_TOOLS=1`，然后重启应用。开发工具只允许在本机回环地址启用。数据库密码以脚本生成的 `.env` 为准，不要替换为示例值。

停止时，先在运行 `npm run dev` 的终端按 **Ctrl+C**，再执行：

```powershell
npm run mysql:stop
```

下次运行 `npm run mysql:start` 会复用现有项目数据库。备份时应保留数据库备份及对应凭据；不要通过删除 `.local/` 来清理普通开发缓存，该目录也保存角色数据。

## 先玩一局

新账号出生于 **Map040「榆风市 · 中央街区」`(20,23)`**。沿街区东侧通道前往 **Map041「榆风广场」**，单击 `(23,12)` 的「远征接引员」自动靠近交谈，或面向 NPC 按 E，创建 PvE 或 PvPvE 副本，在面板点击「开始副本」。其他账号可从同一 NPC 加入等待中的副本；可一人开始，上限八人，每局二十分钟。离开副本后恢复入局前的广场位置与局外背包。

1. **普通撤离**：从村庄 Map011 进入旅店 Map012，搜刮通行证箱，回村口解锁共享出口，再次交互撤离。通行证不消耗；解锁后其他玩家也能撤离。
2. **Boss 终局**：从村庄去道路 Map020 取得解除组件，回村庄进入村屋 Map013，操作控制台解除普通禁区。再从道路经洞穴 Map021 到矿道 Map022，击败封锁守卫并拾取终局钥匙，操作矿道终局出口结束整局。矿道仍是持续禁区，记得使用补给箱里的恢复物品。
3. **永久外观**：从中央街区西北侧进入 **Map043「换装美容工作室」**，与 `(10,8)` 的「外观调整师」交谈。可组合原 CharacterCreator 部件和色板，也可选择已有 Actor 外观；保存后其他玩家能看见，进出副本和重新登录均保留。

局内物资独立，回城恢复局外背包。本轮没有局内物资转永久奖励。死亡在原地掉落一个包含全部随身物品的背包，整包拾取；钥匙可以丢弃转交。断线后角色留场、继续受伤，重连接回其当前状态。在侧栏「离线行动」选择停留、躲避、探物或追杀；设置作为永久资料保存，在线时由玩家接管。

村口补给箱提供投刃与棒槌，旅店保管箱提供火枪与弹药，道路工具箱提供法杖与恢复药水，洞穴补给箱提供后续武器和弹药。装备后选择「普通攻击」，自动使用该武器的攻击方式。武器耐久按单件保存，背包会显示射程、每击消耗及剩余耐久；无需使用开发工具取得这些武器。

详细地图坐标、传送关系和验收步骤见 [客户端验证说明](client/VERIFICATION.md)，副本初版规则见 [第二阶段实施记录](../doc/2026-10-11-playable-instances.md)，新增策略、武器参数和素材来源见 [离线行动、鼠标与武器扩展记录](../doc/2026-10-11-offline-mouse-weapons.md)。副本内关闭开发传送、补物资与重生。外部世界保留原有内容测试入口。

## 公共城市

**Map040–048 是九张局外公共地图**：中央街区、榆风广场、便利商店、美容工作室、市民大厅、公寓门厅、公寓住宅层、政务服务厅和公园。街区、广场与公园连成环线；商店、美容院和公寓从街区进入，大厅与政务厅从广场进入。公共城市没有副本禁区、敌人或本局物资箱，也不属于副本地图集合。

**Map042 便利商店 `(18,13)` 的合成工匠**保留原 Map003 合成入口的命令；其余旧调试奖励、清空背包和测试场景仍留在原地图。远征接引员和外观调整师是 RPG Maker 地图中可见的事件，由新引擎绑定服务；后续调整站位可继续编辑地图事件。

新引擎中仍停留在 **Map001** 的已有角色，下次登录会一次性迁到中央街区，保留背包、金币和事件状态；其他已保存地点保持原位。迁移完成后主动返回 Map001，不会在再次登录时重复迁走。此规则仅适用于新引擎 MySQL 存档；旧 MV 客户端及 RethinkDB 账号、出生配置与存档不做迁移。

布局、素材来源与验收记录见 [公共城市扩张记录](../doc/2026-10-11-public-city.md)。修改地图后重启服务并刷新浏览器生效。

## 副本现代区扩张

大逃杀副本已从 6 张扩展到 **15 张地图**。从道路 **Map020 `(35,8)` 的金色水晶**进入 Map031 地铁站厅；靠近后继续朝水晶移动，或单击水晶即可传送。新区含地铁、地下维护通道、电玩城、夜店、酒店、宿舍、健身房、游泳馆与影院（Map031–039），有回环通路、30 个本局共享箱子及 28 名本局不重生的敌人。原通行证撤离和矿道 Boss 结局继续可用。

新区按整图进入普通禁区：电玩城／夜店／酒店在开局 6 分钟，宿舍／健身房／游泳馆在 8 分 30 秒，影院／地下维护／地铁在 11 分钟；各提前 30 秒预警，村屋控制台一并解除。重启引擎服务并刷新客户端后生效。地图与事件可继续在 RPG Maker 中编辑。

布局、资源来源、碰撞调整及验证记录见 [现代区地图扩张记录](../doc/2026-10-11-modern-district.md)。

## 操作与独立内容测试

| 操作 | 控制方式 |
| --- | --- |
| 移动 | 单击／轻触地面自动寻路；按住并移向新格子改变目的地；WASD / 方向键接管 |
| 攻击 | 单击敌人自动靠近攻击；J / 空格，或右侧“攻击”按钮 |
| 选择技能 | 右侧技能下拉框 |
| 对话、事件交互、附近拾取 | 单击目标自动靠近互动；也可面向目标按 E，或用“交互”按钮 |
| 背包、使用道具、装备 | 右键 / Esc / Tab，或“背包”按钮 |
| 合成 | 右侧“合成”按钮 |
| 取消寻路、关闭背包等面板 | 右键 / Esc / 触屏双指 / 面板关闭按钮；键盘移动也会取消旧路径 |
| 离线行为 | 侧栏“离线行动”选择停留、躲避、探物、追杀 |
| 地图测试 | 右侧地图选择后点击载入；在线传送需要开发工具 |
| 预览视角 | 内容预览中单击地图改变观察中心，或用 WASD / 方向键平移；右下角调整缩放 |

建议先在内容预览中检查熟悉的地图，再注册新账号进行以下测试：

1. 通过开发地图选择进入 **Map024**，检查原有敌人与实时战斗。使用“测试物品与技能”获取测试背包和技能，在下拉框切换技能；也可用“生成附近敌人”构造战斗场景。
2. 用两个独立浏览器会话登录**两个不同账号**，进入同一地图或同一副本。让其中一个角色打开背包或合成面板，另一个继续移动、交互或战斗，观察状态是否继续更新。一个账号不允许同时连接两次。
3. 在 **Map011、Map030** 测试当前启用的 PvP。Map009 也启用了 PvP，但原有并行事件会自动传送角色，持续战斗建议用前两张地图。其他地图默认不允许玩家互相伤害。
4. 测试拾取、装备、合成、死亡掉落和重生。合成仍会检查配方要求，例如材料、等级与配方书；开发测试按钮提供的道具用于方便验证这些流程。
5. 点击“启动禁区倒计时”：当前地图在 10 秒预警后成为测试禁区，持续 30 秒；离开该地图可以避开伤害。这是开发演示，不是完整对局规则。
6. 正常退出、重新登录，核对角色与物品。服务端重启会使内存中的登录令牌失效，需要重新登录；MySQL 中的角色数据仍保留。

当前 **48 张地图**均可载入内容预览，按现有通行数据有 **45 张**能够找到出生点。**Map010、Map026、Map029** 没有可用出生点，在线传送会明确拒绝；预览仍可检查它们的资源。Map026 和部分 Map029 页面属于旧共享变量 PvP 模板，已隔离，不能将其原始模板运行效果当作新引擎支持的玩法。

开发工具会改变测试账号和当前世界状态，建议使用专门的测试账号。

## 当前数据与运行方式

- 导入现有 48 张地图、数据库和事件列表，以及 9 个合成配方、76 个 Chrono 工具定义（含新增四种武器的 Toolmap 事件）。**成功导入定义不等于完整实现其每一种运行语义**。
- 读取项目中启用的 44 个插件的参数和已知内容标记；浏览器和服务端均不执行这些插件的任意 JavaScript。支持的特定脚本写法由显式适配器处理，其他写法进入诊断。
- 服务端按 **20 Hz** 推进世界，按 **10 Hz** 下发完整快照。客户端负责素材呈现和输入；打开菜单只覆盖界面，不暂停服务端世界或网络接收。
- 账号、外部角色、永久外观、对局、参与者、物品和掉落保存到 MySQL/InnoDB。每局使用独立 World 与存储作用域；共享箱子、整包掉落与拾取使用事务和唯一键，带请求编号的操作拒绝重复结算。
- 实时世界仍主要在服务端内存中运行。角色有周期保存，部分操作即时提交；这不等于每一帧、每个怪物、每个事件进度都能在崩溃后精确恢复。
- 地图绘制支持标准 48 px 图块，包括 A1 动画、A2 自动地板与桌沿、A3/A4 墙面、A5/B–E 普通图块、阴影、星标遮挡与 `$` / `!` 人物切片。支持 MV 图像帧动画、MZ `.efkefc` 粒子及部分常用事件表现。Effekseer 使用独立 WebGL 画布合入地图画面；无 WebGL 时报告特效失败，战斗结算仍由服务端进行。
- Effekseer for WebGL v1.52n 的运行库及 MIT 许可位于 [client/vendor/effekseer/](client/vendor/effekseer/)。所选效果来自本地 MZ 样例，来源和依赖记录在 [SOURCE.json](client/vendor/effekseer/SOURCE.json)；效果、纹理和 RPG Maker 素材仍受各自原授权约束，运行库的 MIT 许可不覆盖这些素材。

## 修改内容与查看兼容报告

继续用 RPG Maker 编辑仓库中的地图、事件、数据库和素材，保存后**重启新引擎服务**以重新导入，再刷新浏览器。当前没有完整内容热更新或自建远端地图编辑器。素材由 `/assets/` 直接引用原目录；替换同名图片后若浏览器仍显示旧图，可以强制刷新缓存。

运行离线内容检查：

```powershell
npm run content:check
```

应用启动后可查看：

- [运行状态 `/api/health`](http://127.0.0.1:8098/api/health)：数据库是否就绪、地图数和世界 tick。
- [兼容报告 `/api/coverage`](http://127.0.0.1:8098/api/coverage)：导入器检查结果及本次服务运行中收集的事件诊断。
- 客户端“查看内容兼容报告”：内容统计、本次浏览缺失资源、未适配的表现命令。

兼容报告按具体事件命令和页面标记适配情况。地图能显示、命令能解析或参数能提取，均不能作为“整张地图所有原玩法已经兼容”的证明。

## 自动检查

在 `engine/` 目录运行：

```powershell
npm test
```

默认测试包含内容导入、事件适配、战斗、世界状态、离线策略、鼠标寻路、武器成本与客户端格式解码等检查。需要真实数据库的用例默认不执行。客户端图块回归会将现有地图使用的图块在多个动画帧中的分片坐标，与隔离的旧格式解码函数对照；Effekseer 回归检查变换参数、路径和实际效果依赖。运行中的新客户端不加载旧 RPG Maker 引擎。

先启动项目 MySQL，再运行真实数据库集成检查：

```powershell
npm run test:integration
```

该命令显式启用持久化、局内存储与 HTTP/WebSocket 真实 MySQL 测试。基础存储测试在项目数据库中创建带随机前缀的测试账号和掉落，局内存储和端到端测试创建独立临时 schema；均在结束时精确清理本轮数据。它检查事务、故障重试、永久资料、武器个体及消耗持久化、实例进出与协议隔离；不代表已完成并发容量、长时间稳定性或生产运维验证。

浏览器视觉与交互核对清单见 [client/VERIFICATION.md](client/VERIFICATION.md)。

## 仍需实现或验证的部分

1. **MV/MZ 的兼容范围。** 目前以本仓库 MV 项目作为地图与事件实际输入，并导入 MZ 样例的四个 Effekseer 效果；尚无完整 MZ 项目的回归验证。任意插件运行时、插件专有角色表布局与完整视差插件仍不支持。循环地图数据可读取，摄像机仍限制在地图边界。事件色调和粒子目标闪光属于近似表现；本轮运行库版本不代表兼容所有后来版本的粒子格式。
2. **完整 ARPG 规则。** 现有技能、工具标记和素材只能部分转化为新战斗行为；Traits、TP、完整状态与增益生命周期、所有技能目标范围、装备能力和 Chrono 工具语义尚未完整兼容。装备当前仅有一个武器槽和一个防具槽，不能还原原项目所有装备部位。
3. **事件的多人含义。** 开关、变量、自开关和多数事件任务当前按个人作用域运行；这不是自动继承旧插件的全局共享语义。全局任务、世界唯一物品、队伍作用域及多人共同推进事件仍需明确设计。
4. **条件敌人页面。** 敌人身份按创建时的默认页面标记生成，个人条件页面的显示变化与共享敌人 AI 尚未形成完整一致的语义。不能依靠个人开关切页来可靠创建或销毁全世界共同的敌人。
5. **未实现的旧功能。** 商店、载具、回合制战斗和若干事件输入/表现命令尚未完整实现。导入器或运行诊断会列出不支持内容；不会通过执行旧任意脚本来绕过这些缺口。
6. **大逃杀的扩展。** 已实现一至八人的独立测试局、两条路线、禁区、Boss、共享箱子、死亡背包、结算及四种离线策略；平衡、更多普通 PvE 敌人、队伍规则和观战仍需扩展。离线 AI 使用有界寻路、可达静态传送口与既有战斗／库存规则，不能自动解释任意剧情或保证安全撤离。当前使用整张地图作为禁区单位。其他旧地图的个人条件页不会自动变成本局共享机关。
7. **长期在线与迁移。** 尚无旧 RethinkDB 账号/存档迁移工具，也未完成多进程世界管理、完整世界检查点、生产备份恢复、容量压测、完整反作弊与公开运营部署。应先在本机验证内容与玩法，再推进这些工作。
